# 도시 속 빛나는 존재 · VS Code 개발 패키지

## 바로 실행하기

1. ZIP 압축을 풀고 VS Code에서 `city-of-light` 폴더를 엽니다.
2. VS Code의 Live Server 확장을 사용하는 경우 `index.html`을 우클릭하고 **Open with Live Server**를 선택합니다.
3. 또는 Node.js가 설치되어 있으면 터미널에서 `npm start`를 실행하고 `http://localhost:8765`를 엽니다.

별도 빌드나 패키지 설치는 필요 없습니다. 이미지 픽셀을 읽어 충돌을 검사하므로 HTML 더블클릭 대신 로컬 웹서버를 사용하세요.

## 실제 플레이 화면

`index.html`은 캐릭터가 직접 이동하는 야외 플레이 샘플입니다. 캐릭터 추적 카메라, 발 중심 충돌, 방향키/WASD 이동, E/문 클릭 조사, M 전체 지도, F2 개발자 표시를 제공합니다. 전체 지도에는 장소명과 현재 위치가 표시되지 않습니다. 카메라 확대는 이동 화면에만 적용되며 전체 지도는 회전·확대하지 않습니다.

사진관·학교·집은 조사 시 `city:enter` 이벤트를 발생시킵니다. 이 샘플은 연결 메시지를 보여 줍니다. 실제 실내 장면과 퍼즐, 저장 시스템, NPC는 아직 구현하지 않았습니다. 놀이공원·놀이터는 야외 상태를 유지합니다. 입장은 단서·업적·아이템 확인으로 제한하지 않습니다. 집 정문은 잠금 메시지를 표시하고, 북쪽 뒷마당 쪽문은 별도 골목으로 접근할 수 있습니다.

## 캐릭터 규격

프레임은 256×256입니다. 행은 위에서부터 아래보기 / 왼쪽 / 오른쪽 / 위보기입니다. 열은 0–3 순서로 7fps 루프합니다. 정지 시 1열(0 기준)을 사용합니다. 앵커는 프레임 기준 `(0.5, 0.97)`이며 논리 월드에서 높이 42로 표시합니다. 충돌은 그림 전체가 아닌 발 중심 반경 3입니다. 대각선 이동은 속도를 정규화합니다.

생성형 회화 스프라이트로 측면의 반대발 구분과 보폭 차이가 미세합니다. 출시용으로 사용하기 전 원하는 크기와 속도에서 동작을 검토하세요. 고전 픽셀아트 시트가 아니므로 부드러운 이미지 보간을 유지하는 편이 어울립니다.

## 기획서 반영과 제작 시 결정한 부분

논리 공간은 1000×900, 원점 왼쪽 위, 동쪽 +X, 남쪽 +Y, 북쪽은 항상 위입니다. 핵심 대표 좌표는 다음과 같이 고정했습니다. 이 좌표는 실제 문이 아닙니다.

| ID | 장소 | 대표 좌표 | 제작한 실제 입구 | 처리 |
|---|---|---|---|---|
| C01 | 사진관 | 170,565 | 135,590 | 남서 거리에서 접근, 실내 연결 |
| C02 | 학교 | 265,305 | 265,350 | 시계탑 인근 분기, 실내 연결 |
| C03 | 놀이공원 | 774,345 | 712,365 | 서쪽 단일 진입로, 야외 유지 |
| C04 | 놀이터 | 809,571 | 760,620 | 남서 울타리 출입구, 야외 유지 |
| C05 | 집 | 533,778 | 533,747 | 동쪽 골목을 통한 북쪽 쪽문, 실내 연결 |

분수·시계탑·연못·큰 나무를 배치했습니다. 큰 나무는 놀이터 서쪽 외곽입니다. 놀이터 그네는 북서, 미끄럼틀은 북동, 시소는 동쪽입니다. 놀이공원에는 매표소, 회전목마, 판매대가 있습니다. 회전목마 도형은 말 6개와 마차 3개를 표시하지만, 실제 근접 퍼즐의 가림·관찰 연출은 별도 상세 스테이지에서 구현해야 합니다.

북쪽 순환도로는 동쪽으로 진행한 후 남동쪽으로 우회전합니다. 학교 주변 비대칭 분기는 단서용 SVG와 같은 도로 데이터에서 생성했습니다. 집 정문 접근로와 쪽문 접근로는 별도 도로입니다. 단서 낙서·놀이터 메모의 완성 삽화는 이번 범위에 포함하지 않았으므로 제작할 때 `world.json`의 시설·골목 좌표를 재사용하세요.

기획서 27쪽에서 미정으로 남긴 최종 도로·문·랜드마크 세부 좌표, 캐릭터 크기·속도는 이 패키지의 **제작 제안값**입니다. 다섯 대표 좌표와 진입 규칙은 기획서를 따릅니다. 지도 PNG는 따뜻한 파스텔의 간결한 벡터 그래픽이며, 별도 참고 일러스트와 그림체·정보 밀도가 다릅니다.

## 기존 게임에 연결하기

`game.js`의 이미지 로딩·발 충돌 코드를 그대로 사용하거나 PNG와 JSON만 가져갈 수 있습니다. 다른 해상도로 표시할 때는 이미지와 좌표를 같은 배율로 변환하세요. Phaser라면 스프라이트 프레임 크기를 256×256으로 설정하고, 바디는 발 위치에 맞추세요.

실내 전환 연결 예:

```js
window.addEventListener('city:enter', ({ detail }) => {
  if (detail.mode === 'interior') {
    // loadScene(detail.target, detail.returnPosition);
  }
});
```

진입은 가까이에서 E 또는 클릭으로 작동합니다. 위치에 닿는 즉시 자동 전환하려면 `inspect()` 호출 조건을 수정하세요. 실제 게임에 통합할 때는 샘플의 안내 dialog를 제거하고 장면 관리자로 연결하세요.

`world.json`과 `world.js`는 같은 내용을 유지해야 합니다. 맵 원본·충돌 마스크·좌표 데이터도 함께 갱신하세요. 그림만 교체하면 보행 경계가 맞지 않습니다.

## 검증 범위

발 반경 3을 적용한 마스크에서 출발점부터 다섯 입구와 잠긴 정문까지 연결성을 검사했습니다. PNG 크기와 실제 알파 채널을 확인했습니다. 이 샘플은 완성 게임이 아니며 실내·퍼즐·애니메이션 세부 연출의 최종 플레이 테스트는 별도로 필요합니다.
